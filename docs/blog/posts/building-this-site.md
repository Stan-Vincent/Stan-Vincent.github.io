# 这个主页是怎么做出来的：一个<span class="nowrap">强调色</span>与<span class="nowrap">几段图标变形</span>

<ArticleMeta />

> 这篇文章写的是第一版手写主页的实现。现在站点已迁到 VitePress：文章用 Markdown 编写，侧栏和文章列表自动生成；配色、静态背景和首页结构沿用。

这一版主页的目标很明确：保留“有动效”的感觉，但把颜色和背景收干净。最后的做法可以概括成一句话：静态的背景，单色的界面，动效只出现在需要它解释状态的地方。

## 先收颜色：一套设计令牌

整站只有两组中性色加一个强调色。浅色和深色共用同一套变量名：

```css
:root {
  --bg: #fafafa;
  --surface: #ffffff;
  --line: #e7e7ea;
  --ink: #18181b;
  --body: #52525b;
  --mute: #6f6f79;
  --accent: #0a5bd3;
}

html.dark {
  --bg: #08080a;
  --surface: #0e0e11;
  --line: #232328;
  --ink: #f4f4f5;
  --body: #a1a1aa;
  --mute: #83838d;
  --accent: #7cb2ff;
}
```

强调色只出现在几个地方：标题里的半句话、区块编号、悬停状态、阅读进度和链接。其余全部是黑白灰。颜色一少，间距和字重的层级反而更清楚。

## 背景为什么不动

之前那版主页用了四色流动渐变和毛玻璃。它确实“有动感”，但所有元素都在动，反而没有重点。现在背景只剩一层静态网格和顶部一层很淡的光晕，滚动时不会跟着晃。

这个决定来自 morphicons 的网站：它的设计注释里写着 “Static on purpose; motion lives in the morphs.” 背景是静的，动效留给图标变形。对个人主页来说，这句话很好用：背景负责氛围，动效负责反馈。

## 图标变形怎么做

第一版首页需要变形的图标不多：外链箭头、查看项目箭头、移动端菜单。每一对图标都表示成 24×24 网格上的折线点集，例如右箭头和右上箭头：

```js
const ICONS = {
  right: [
    [[4, 12], [20, 12]],
    [[13, 5], [20, 12], [13, 19]]
  ],
  upRight: [
    [[5, 19], [19, 5]],
    [[8, 5], [19, 5], [19, 16]]
  ]
};
```

变形时先按弧长把每条折线重采样成相同数量的点，再逐点插值。这样不需要处理贝塞尔曲线，也不必引入图形库：两组点一一对应，中间的每一帧就是一行 `d` 字符串。

```js
function buildPath(a, b, t) {
  let d = '';
  for (let s = 0; s < a.length; s++) {
    for (let i = 0; i < a[s].length; i++) {
      const x = a[s][i][0] + (b[s][i][0] - a[s][i][0]) * t;
      const y = a[s][i][1] + (b[s][i][1] - a[s][i][1]) * t;
      d += (i === 0 ? 'M' : 'L') + x.toFixed(2) + ' ' + y.toFixed(2);
    }
  }
  return d;
}
```

进度 `t` 不是固定时长的缓动，而是用弹簧积分算出来的：

```js
v += (420 * (target - t) - 30 * v) * dt;
t += v * dt;
```

420 是刚度，30 是阻尼。鼠标移开时目标变回 0，弹簧会从当前位置和当前速度继续走，所以中途打断也很自然。第一版的所有图标共用这套逻辑，只在悬停、聚焦和菜单展开时触发。

## 阅读体验

第一版博客补上了几件文档站常见的事：文章列表、左侧文章栏、右侧本页目录、阅读进度条、代码复制按钮、上一篇/下一篇。它们都不是装饰，而是让长文章更好读。

目录不是手写的：页面加载后从正文里的 `h2` / `h3` 生成，滚动时高亮当前章节。代码块复制按钮也是同一套思路：只在有 `pre` 的页面出现，不污染正文结构。

迁到 VitePress 后，目录、上一篇/下一篇、代码复制和搜索变成了内置能力；文章元信息和阅读进度由一层很薄的自定义主题补上。

## 可访问性上的几个决定

- **键盘可达**：所有交互都有 `:focus-visible` 轮廓。
- **状态可读**：导航用 `aria-current`，菜单用 `aria-expanded`，移动端菜单关闭时设为 `inert`。
- **减弱动效**：系统开启 `prefers-reduced-motion` 时，变形直接跳到终点，不做过渡。
- **无 JS 也能读**：正文默认可见，滚动显现只在 `html.js` 下才隐藏元素。

## 迁到 VitePress 之后

现在文章源文件是 `docs/blog/posts/*.md`，标题、日期、标签、摘要写在 frontmatter 里。侧栏和文章列表在构建时从这些 Markdown 里读出来，新增一篇文章不需要再同步三四个 HTML 文件。

写法变成了这样：

```md
---
title: 一篇文章的标题
date: 2026-10-26
tags: [C++, Qt]
description: 一句话摘要
---

正文从这里开始。
```

构建时运行 `npm run build:site`，VitePress 生成静态页，脚本再把产物复制到仓库根目录，GitHub Pages 继续从根目录发布。

## 小结

这套站点的核心不是某个炫技效果，而是把“动”限制在少数几个地方：图标变形、滚动显现、导航高亮和阅读进度。颜色和背景越安静，这些动效越容易被注意到。

第一版是纯静态的 HTML/CSS/JS，没有构建步骤；现在用 VitePress 负责导航、搜索、目录和文章组织，设计和内容仍然保持单色、克制。写一篇新文章只需要在 `docs/blog/posts/` 放一个 Markdown 文件，侧栏和列表会自动更新。
